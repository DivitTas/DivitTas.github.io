When two players grab the same bowl across 80ms of latency, who wins? A short note on authoritative kitchens.

## The problem

Two players reach for the same bowl of soup at the same time. On each client, they each see themselves holding it. On the server, only one of them can be right. This is the fundamental problem of multiplayer object ownership.

## The solution

The server is always authoritative about who holds what. When a player tries to pick something up, they send a request. The server grants it or denies it. On the client, we *predict* the pickup immediately (optimistic update), then reconcile when the server responds.

If the server says "no, the other player got it first," we snap back. This produces a brief visual glitch — but 80ms of latency means it's nearly invisible in practice.

The harder problem is visual continuity. We lerp the bowl back to its correct position rather than teleporting it. Players notice the correction less when it's smooth.
